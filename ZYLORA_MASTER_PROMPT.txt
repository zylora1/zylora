# 105. ROOT-CAUSE POLICY

This rebuild exists to eliminate patch-on-patch development.

If multiple bugs share a pattern:

STOP.

Find the common abstraction.

Examples:

```text
8 plan bugs
→ Entitlement Engine

6 publish bugs
→ Deployment State Machine

10 ownership bugs
→ Ownership Service

many style inconsistencies
→ Design System

hundreds of similar bad Templates
→ Template-generation methodology
```

Fix root cause.

Then add regression tests.

Do not patch hundreds of symptoms.

# 112. CRITICAL AUTOMATED INVARIANTS

Explicitly test:

### ROLES

Only User + Super Admin.

### MULTI-TENANCY

Isolation without organizations/workspaces/additional roles.

### OWNERSHIP

Exactly one current owner per Website.

### LIVE SITE

Maximum one published Website per User.

### CREATION

Every Website begins from approved Template.

### PORTAL

One User portal.

### PUBLISH

Server-authorized only.

### PLAN

Server-authoritative eligibility.

### PRICING

Configuration/database-driven.

### PAYMENT

No paid capability from frontend trust.

### TRANSFER

Atomic ownership change.

### EXPORT

No Website ZIP before trusted payment verification.

### ACCOUNT DATA EXPORT

Cannot bypass paid Website ZIP.

### LEADS

One successful valid Lead = exactly one credit transaction.

### FAISS

No cross-tenant retrieval.

### TEMPLATES

Only validated/approved Templates visible.

### ADMIN

Sensitive changes audited.

### LEGACY

No removed V1 architecture hidden behind feature flags.
